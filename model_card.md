Model Card — LegalHelp Retrieval Engine

 Model Details
- Название: LegalHelp Retrieval Engine (RAG-ядро)
- Версия: 1.0
- Тип:Гибридная поисковая система (BM25 + векторный поиск на эмбеддингах)
- Модель эмбеддингов: all-MiniLM-L6-v2 / intfloat/multilingual-e5-large`
- Генеративная модель: llama3.1:8b (через Ollama)
- Разработчик: Шолбан Донгак
- Дата: октябрь 2026
- Лицензия: Apache 2.0 (эмбеддинги), MIT (проект)

Intended Use
Основное назначение
- Семантический поиск релевантных статей федеральных законов РФ по запросу на русском языке.
- Поддержка RAG-пайплайна для генерации юридических ответов и черновиков документов.

 Предполагаемые пользователи
- Юристы, адвокаты, студенты юридических специальностей.
- Организации, которым критична конфиденциальность данных (152-ФЗ, адвокатская тайна).

Использование вне рамок
- Не заменяет профессионального юриста.
- Не предназначена для принятия юридических решений без human-in-the-loop.

Factors
- Язык: русский (основной), английский (ограниченно).
- Область права: федеральное законодательство РФ (кодексы, ФЗ).
- Длина запроса: 1–500 символов.

                      Metrics

            Метрики поиска (ранжирование)

| Метрика                    | Значение | Что означает |
|----------------------------|---       |--------------|
| Precision                  | 0.87     | Из 5 найденных чанков 87% релевантны запросу. Показывает точность топа. |
| Recall.                    | 0.84     | Из всех релевантных чанков 84% попали в топ-5. Показывает полноту. |
| MRR (Mean Reciprocal Rank) | 0.84     | Средний обратный ранг первого релевантного результата. MRR=0.84 означает, что в среднем первый релевантный чанк находится на позиции ~1.2. Чем ближе к 1.0 — тем быстрее пользователь находит нужное. |

Формула MRR: для каждого запроса RR = 1 / (позиция первого релевантного). MRR = среднее RR по всем запросам.

 Метрики классификации (бинарная задача «релевантно / нет»)

| Метрика  | Значение | Что означает |
|--------- |----------|--------------|
| Accuracy | 0.87     | Доля правильных предсказаний. При дисбалансе классов может вводить в заблуждение. |
| Precision| 0.86     | Из предсказанных «релевантных» 86% реально релевантны. Защита от «мусора» в топе. |
| Recall.  | 0.84     | Из всех реально релевантных 84% найдено. Защита от пропусков. |
| F1-score | 0.85     | Гармоническое среднее Precision и Recall. Баланс между точностью и полнотой. |
| ROC-AUC  | 0.89     | Площадь под ROC-кривой. Показывает качество ранжирования независимо от баланса классов. 0.5 — случайно, 1.0 — идеал. |

 Сравнение стратегий поиска

| Стратегия       | Precision@5 | Recall@5 | MRR  |
|-----------      |-------------|----------|----- |
| Векторный поиск | 0.62        | 0.58     | 0.58 |
| Гибридный поиск | 0.87        | 0.84     | 0.84 |

Вывод:гибридный поиск превосходит векторный на 25–30% по всем метрикам.

Evaluation Data
- Объём: 500 юридических вопросов с эталонными ответами.
- Источник эталонов: действующие федеральные законы РФ (pravo.gov.ru / RusLawOD).
- Разбиение:70% — валидация, 30% — тест.

 Training Data
- Источник: корпус RusLawOD (304 862 XML-файла, 1991–2025).
- Обработка: чанки ~500 символов, перекрытие 50, эмбеддинги.
- Всего чанков: ~5 011 677.

Ethical Considerations
- Конфиденциальность: всё локально, данные не покидают устройство (152-ФЗ).
- Прозрачность: каждый ответ со ссылкой на источник.
- Ограничения: возможны галлюцинации (~8%), база неполная (нет судебной практики и региональных актов).

 Caveats and Recommendations
- Всегда проверять сгенерированные документы у юриста.
- Для критичных задач использовать в паре с коммерческими СПС.
- В перспективе — fine-tuning эмбеддингов, каскад LLM, граф знаний.

Ограничения ML-эксперимента

- Датасет: 50 примеров, дисбаланс 45:5. Метрики 1.0 в `ml_experiments/results.md` — артефакт малой выборки и утечки признака `bm25_hint`, а не реальное качество.
- Разметка эвристическая (по ключевым словам), не ручная.
- Для production: 500+ примеров, ручная разметка юристом, удаление `bm25_hint`, кросс-валидация.
- Шаблоны документов (`templates/`) — отдельная часть проекта, в ML-обучении не участвуют.
